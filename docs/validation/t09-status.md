# T09 确定性采样验证

最终验证日期：2026-10-26。本轮把规范化 ReplayData 转为 TargetFrame，仍属于 CPU 数据处理；没有运行回放时间轴、正式 HTTP 会话、IsaacSim worker 或媒体联调。

## 完成范围

- 按通道预处理、二分定位与线性插值，在同一请求时刻使用各通道自己的邻接采样点。处理原时间起点偏移、首末 clamp、单样本、原采样索引与前后单步。
- 有限位旋转与移动关节不夹紧、不擅自包角；累计连续角原样保留。声明为包角的通道按有效源序列预先展开，保留推算/插值来源，不能据此恢复原日志未记录的整圈。
- 缺测区间不伪造有效值。关节目标需要有限数值时，只从查询时刻之前的源历史确定无效回退；没有历史则无效零值，不依赖上一次 seek。底盘只在三个 world 通道都有效时返回位姿。
- 只有明确启用并配置半径及三个关节符号时，才为整个源通道均无有效值的轮关节预计算视觉滚动角；保留已有有效源通道，缺口不混补。模型为带符号的底盘中心前向位移估计，不模拟各轮转向/安装偏移。
- 实际 CSV/JSON 隔离导入、归档、采样的集成验证，确认原始角度、源文件与归档不被采样修改。

## 测试与审查

最终 **441 项后端测试通过**：164 contracts、199 adapters、78 replay。既有 P0 CPU unittest 使用原系统 Python 环境运行，**90 项通过**。Schema 导出校验和 TypeScript 契约检查通过；wire Schema 没有变化。

独立审查发现并修复一项 Important 问题：虚拟轮积分原先只检查端点，可能跨过被 `max_gap_s` 判为不可用的中间区间。新实现用预先计算的无效边计数检查整个区间；有无无关关节的中间时间戳，都不能让缺口后的累计轮角恢复为有效。两个回归用例先失败后通过。无剩余 Critical/Important/Minor 审查项。

既有 Starlette/httpx TestClient 弃用 warning 仍存在。P0 探针与纯后端使用独立 Python 环境；直接在后端 venv 对整个 `tests/` 目录运行 pytest 会遇到旧 P0 NumPy 依赖，因此分别运行项目配置的 pytest 与既有 unittest 命令，不据此增加后端依赖。

## CPU 探针

合成输入含 1,200 个原时刻、28 个关节目标。准备一次约 **0.264 秒**；2,000 次顺序目标查询约 **0.337 秒**，平均 **0.169ms/次**（约 5,930 次/秒）。之后对同一批时刻执行固定种子的随机顺序和逆序，共验证 6,000 次目标查询的一致性；共享协议 JSON、原采样索引、正负轮角和源数据不变均通过。

这些数值是本机 CPU 目标生成开销，包含当前数据规模与模型假设，不代表 IsaacSim 渲染帧率、视频延迟或最终回放吞吐。示例半径 0.1m 和关节方向仅属于合成探针，不是确认的 R1 参数。

精确数据见 [t09-evidence.json](t09-evidence.json)。原始日志和 JUnit 位于 `outputs/t09/20261026/`，最终探针与最后目标帧位于 `outputs/t09/probe-20261026/`，均不纳入源码 Git。重跑时使用不存在的新输出目录：

  --output-dir outputs/t09/new-probe
