- 拥有的 worker SIGKILL 后 **882.145ms** 显示错误；重新创建新 sid 并从日志 0 秒加载。
- 拥有的 MediaMTX 被终止后 **1275.958ms** 恢复新网关后的实际新捕获帧，排除了旧缓冲画面冒充恢复。

## 资源与 CPU 口径

资源摘要只取实际 soak 起止区间，排除创建和销毁；每约 5 秒采样。RSS 会重复计算共享页，自动化驱动与实际浏览器分开统计。

| 组件 | 平均单核 CPU | 平均整机 CPU（24 核） | 首尾稳定分钟 RSS 变化 |
| --- | ---: | ---: | ---: |
| API 主服务 | 12.406% | 0.517% | -2.926MiB |
| 实际浏览器 | 74.799% | 3.117% | +46.799MiB |
| SDK worker | 97.395% | 4.058% | +15.809MiB |
| MediaMTX | 2.427% | 0.101% | +2.456MiB |
| 自动化驱动 | 2.401% | 0.100% | -5.274MiB |

worker 显存的首尾稳定窗口均为 **1723MiB**。浏览器与 worker 有小幅 RSS 增长，应保留长期观察；30 分钟结果不证明无限期无泄漏。

原计划“20Hz 遥测下主服务 CPU<5%”没有明确分母。本机按整机口径低于 5%，按单核口径未达到；两者不可互换。本报告完成口径复核，未将该单核目标标为通过。后续若将单核 5% 定为交付硬门槛，仍需针对主服务采样/序列化开销优化；服务器性能也需要重新实测。

## 本轮修复与失败记录

1. 新目标已完成物理步进/读回，采集时又重复执行。现在只复用一次新鲜读回，后续保持帧仍逐次刷新；失败清空缓存，完整目标身份必须一致。
2. SDK 默认多传感器异频模式在同步采集后额外更新两次应用。单相机 worker 显式关闭 `supportMultiTickRate`，保留分辨率、画质、渲染完成等待及像素身份屏障。诊断中的渲染编排均值从约 40.80ms 降到 21.33ms；正式长测另行取证，不继承短探针通过。
3. 长测原先代理所有 WS 消息，并为大量纯数值断言生成框架步骤。Playwright 会保留消息参数到测试结束，造成测试工具内存开销。现在健康长测使用原生 WS，纯数值检查使用普通断言，门槛与容差不变。失败长测和主动中止的诊断运行均保留。
4. 有损 WebM 的 JPEG→VP8 两次编码使细小青色文字未通过固定 38 的差异门槛。改用原始屏幕 PNG，并对齐整数像素；阈值没有调松，14/15px 青色单数字 0→8 的故意错误仍被检出。原失败视频、逐帧报告与诊断图保留。
5. 刷新原先依赖测试脚本 DELETE，现由应用跟踪本标签页成功创建的 sid，在 reload 时先清理再允许新建；失败可重试，404 视为已释放，普通导航/复制页不接管旧凭据。迟到的旧创建响应不能覆盖新会话的所有权记录。

一次完整独立审查及新增刷新逻辑的专项跟进共提出 4 项 Important、1 项 Minor，均已修复或通过明确证据范围处理。包括录屏结果纳入总通过门槛、发信号前紧邻复核 PID、短尾窗结算以及迟到创建凭据竞态。

## 回归与边界

后端 953 项（另 5 子测试）、前端 264 项、既有 Chrome 14 项、P0 CPU 90 项、系统录屏测试 16 项、Schema/TS 与构建通过。后端的 3 项可选跳过分别为独立工具环境的 PyArrow 分支与系统 OpenCV 检查；不为此往 HTTP/SDK 环境安装依赖。

- 故障注入是本地消息层与拥有进程中断，未执行 IP/RTP 网络层丢包或远程服务器验收。
- 长测先于新增刷新生命周期补丁；长测覆盖的同会话播放路径未改，新增刷新/复制页/清理分支由最后完整真实矩阵和回归覆盖，不声称重跑了补丁后的 30 分钟。
- 页面在创建响应返回 sid **之前**被强制销毁，尚无服务器所有权租约恢复机制；不通过猜测会话或删除其他客户端资源来处理。
- 夹爪精确标定、底盘真实语义和同次完整 MCAP 仍为后续数据确认范围。
