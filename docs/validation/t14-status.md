## 实际 HTTP/WS、SDK 与视频

原始证据：`outputs/t14/api-real-2/`，摘要：[t14-evidence.json](t14-evidence.json)。验证脚本：`scripts/validate_api.py`、`scripts/observe_api_video.mjs`。

- 合成 121 样本、28 关节 CSV 经真实 HTTP multipart 上传，标记 commanded；上传前后原件 SHA256 一致，上传不自动激活回放。查询通道和曲线正常。
- 实际执行 load、play、10x、pause、seek、前后原采样点 step、stop；HTTP 返回 accepted 后等待 WS 的对应实际渲染快照。
- 独立软件 H.264 解码 **280 帧**，每帧像素 ID/CRC 与正式 SEI 目录唯一匹配，所有视频快照的源值与保存的 CSV 独立插值结果一致，SDK 读回误差小于 1e-5。
- **271 帧**在 WS 找到相同 capture ID，全部字段相等；另 **9 帧**位于控制切换末尾，属于已被新控制替换的旧上下文，因此没有对外 WS 匹配，未用最新数据补配。最终 stop 的 197 帧全部匹配。浏览器正式呈现仍应以每帧 SEI 目录和当前操作屏障为准，不能假设每一编码帧都有 WS 副本。
- Chrome 通过真实 WHEP 接收 1280×720 图像；独立检查 5 个实际视频帧的像素 ID/CRC，均找到 stop/0 秒的对应 WS 记录。截图 `outputs/t14/api-real-2/browser.png` 已检查，显示真实机器人。
- 原始采集短窗口 **17.94fps**；该数值不是浏览器呈现帧率或端到端延迟。本轮未重新测量共同延迟，不代替 P0 的同步性能证据。
- 自有 worker SIGKILL 后 **0.647 秒** HTTP 状态进入错误，WS 收到故障事件；幂等删除后新 sid、新连接从 `capture_id=1 / log_time_s=0` 重载。自有服务、worker、浏览器、网关和端口已清理。

第一轮真实流程发现故障事件被重同步队列清除，已以失败测试复现并修复：保留生命周期事件顺序、替换旧同步通知。第二轮完整重跑通过；首轮失败日志保留在 `outputs/t14/api-real-1/`，不作为通过证据。

API/同步专项覆盖真实 CPU worker 进程与 ZMQ、REST 错误/上传流式限额、WS 重连元数据、客户端身份、慢发送期限、8 客户端容量、健康 10Hz 不降低 20Hz 帧配送、媒体中断状态与质量伪造拒绝。CPU worker 仅是测试替身，生产入口没有假 worker 模式。
