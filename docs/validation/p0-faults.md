# P0 故障与重载验证

2026-10-23，`outputs/p0/faults-final/`，真实 IsaacSim 6.2 → MediaMTX → Chrome 链路，9 个场景全部通过，77 次独立画布 ID＋CRC 校验未检出错配。测试先确认 0.1x 控制已经呈现、日志时间与机器人姿态确实前进，再执行故障；不是用静止 ready 状态替代运动中的验证。

| 场景 | 验证结果 |
|---|---|
| 无 RTSP 源时连接 | 明确连接失败，零帧、零伪造快照，PC 与网关会话释放 |
| 启动源后重连 | 真实解码恢复，初始 ready / log 0 |
| 丢弃元数据消息 | 视频侧继续到达，同步 canvas 和 last_metadata 整体保持；恢复后继续运动 |
| 丢弃已解码图像消息 | 元数据侧继续到达，画面和数据整体保持；被丢 VideoFrame 正确关闭 |
| 消息乱序 | 实际 Worker 消息延迟交错，旧帧不回退，恢复正常后继续配对 |
| 消息重复 | 实际数据克隆与 VideoFrame 克隆重复投递，未发生错误身份配对 |
| 真实网关停止/重启 | 原进程 SIGTERM，画布冻结并提示等待；新网关与新 WHEP 连接恢复 |
| 浏览器刷新 | 新文档、新 WHEP 资源，旧服务端会话清理；恢复相同源会话的正确帧 |
| worker SIGKILL/重载 | 真实源进程组 SIGKILL，新进程/目录/session_id；旧画面共同保持，显式重连后 ready / log 0，新采集编号不混入旧会话 |

消息丢弃、重复和乱序发生在浏览器接收真实 Worker 消息的边界；没有修改源快照或伪造视频。它们**不是 IP/RTP 丢包压测**。网关停启和 worker 强制退出是真实进程操作，且仅针对监督器自己创建的进程。

冻结期间通过整张 canvas 的 SHA256、已呈现元数据及呈现计数一起核验；等待提示可以变化。恢复期间独立解析画布 64 个像素，验证时间和姿态继续变化。同一次 worker 重载后必须从头等待播放，不能继承之前的播放进度。

最后在延迟队列仍有真实消息时断开，验证所有 PC 关闭、Worker 终止、待投递 VideoFrame 清理、WHEP DELETE 成功及网关会话数归零。监督器报告自有进程全部回收，相关监听已关闭。
