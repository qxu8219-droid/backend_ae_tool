# T10 回放状态机与时间轴验证

日期：2026-10-26。已实现可由 fake worker 验证的时间轴核心与回执管理；没有启动实际 worker、ZMQ、编码器或浏览器，也未绑定正式 REST/WS 服务。

## 完成范围

- idle/ready/playing/paused/ended/error 与七类控制的完整转换矩阵；严格校验、重复命令、playing 下 load、末尾重播、零时长与原采样点步进。
- 可注入单调时钟、默认 60Hz 的目标发布节奏、速度切换前按旧速度结算位置；调用方显式 tick，错过的普通目标不补发成积压。
- 控制序号、播放代次与目标序号分开；load/seek/stop/step/重播切换代次，暂停使用顺序屏障。旧会话、日志、代次、控制或未发出的目标不能作为当前证据。
- 关键目标走顺序 RPC 前置操作与关键帧；接受/应用回执不足以结束等待，匹配的渲染证据才解除当前关键等待。等待期间不消耗逻辑播放时长，仍不宣称浏览器已显示。
- RPC 队列最多两个、在途 RPC 最多一个、待发送普通目标最多一个，已发目标记录默认 64 条。新明确控制取代旧意图；首帧、末帧、seek 和单步的当前关键目标走可确认路径。
- 延迟、乱序、重复、错误、超时及伪造来源字段的回执处理；终态 error 后必须新建会话并从头载入。

## 最终验证

**655 项后端测试通过**：164 contracts、199 adapters、292 replay，其中 T10 新增 214 项。T10 包含 42 个独立状态/控制矩阵单元格及 7 个重复控制用例、107 项交付与证据管理测试，以及控制时钟、故障和审查回归。

既有 **90 项 P0 CPU unittest 通过**，使用其原系统 Python 环境。Schema 导出校验与 TypeScript 契约检查通过，wire Schema 不变。仅有既存 Starlette/httpx TestClient 弃用 warning。

集成探针实际生成并导入 121 个原采样点、2 秒合成 CSV，经归档、ReplaySampler 和 Timeline，完成 11 个记录阶段：载入接受/确认、半速播放、暂停、速度切换、延迟关键回执、帧定位/单步、末尾可靠确认、重播、超时拒收迟到证明以及新会话从零重载。过程中发送 26 个普通目标给 fake worker，得到 40 份合成渲染回执；这些数量不是实际渲染帧率或媒体性能证据。

独立审查发现两个 P2 边界问题，均完成失败复现与修复：关键目标安装期间的第二次时钟读取异常未进入终态；极端有限目标频率导致错过 tick 的商溢出。现在安装异常关闭交付，节奏计算使用有限余数和可表示的后继时刻；同一时钟值不会因极端频率重复产生普通目标。全部回归通过，无剩余审查项。

精确数值、用例分类见 [t10-evidence.json](t10-evidence.json)。原始测试/JUnit/契约输出在 `outputs/t10/20261026/`，探针日志、归档与逐阶段快照在 `outputs/t10/probe-20261026/`，不纳入源码 Git。

## 运行与边界

```bash
env -u PYTHONPATH -u PYTHONHOME .venv/bin/python scripts/validate_timeline.py \
  --output-dir outputs/t10/new-probe
```

探针需要源码目录中的测试替身支持，输出目录必须不存在。实际 tick 调度、传输、会话生命周期、真实 worker 以及媒体同步将由 T11～T15 继续实现。后续构造 FrameSnapshot 时必须关联相应 target/control 的状态与速度，不能把最新 Timeline snapshot 随意回填到旧帧。
